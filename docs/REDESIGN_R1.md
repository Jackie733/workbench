## 3. readiness 与 attention 契约

- readiness 在渲染时由 `context.readiness(requirement, ui)` 派生，输入是已加载的 `handoff.workflow`、`trace.results`、`review.data`；它不写阶段、不递增修订、不缓存为授权凭证。
- 只有同一套 `lib/validity.luau` 的批准与验收判定为通过，且阶段允许时，才显示“可以验收”等成功态；缺快照、记录损坏或证据过期一律为未知／未通过。
- 阻断项文案与“下一步”动作直接来自门禁原因：缺快照 → 读取代码快照；缺证据 → 补齐验证证据；阻断发现 → 处置阻断发现。
- “需要处理”由宿主对每个需求读取 `workflow／plan／results／reviews` 后派生，条件键稳定（投递待核对、阻塞、授权失效、待批准、缺快照、阻断发现、必需条件缺证据、可验收），每个需求只显示一次并附多条原因。读取失败显示为错误项而不是隐藏。最多扫描 40 项需求并显式提示截断。
- 活动是同一事件流的跨需求投影；导出只写事件索引（时间／需求编号／类型／摘要／引用），不含验证输出、聊天或凭据。
- R1 不实现未读通知：需要处理只表达未解决的可执行条件，读取它不会清除任何门禁。

## 4. 自动验证

环境：WSL Ubuntu；Lune 0.11.1；Bun 1.3.14。

| 命令 | 结果 |
| --- | --- |
| `lune run tests/run-views.luau` | 1051 checks, 0 failures |
| `lune run tests/run-host.luau` | 55 checks, 0 failures |
| `lune run tests/run-validity.luau` | 53 checks, 0 failures |
| `bun test omp/` | 28 pass, 0 fail |

修复：Tern 会把非按钮节点上的自定义动作名在第一个 `=` 处拆成 `act`／`value`（按钮节点保留完整名）。看板卡片、需要处理卡片与表格按钮单元格使用的 `requirement=`／`review-inline=` 因此到不了宿主的动作路由，表现为点击无反应。宿主现在只对 `requirement=`、`change:`、`review-*` 这三类自身动作重新拼接，其余带值事件不改写；新增宿主回归覆盖分裂形式。

新增覆盖：

- 三种目的地与五种工作区标签都可渲染；未知标签不切页；未知动作被忽略。
- 选择需求进入工作区需求页；返回保留选中项；布局切换并跨重载保留；工作区重载恢复标签与选中项。
- readiness：缺快照必须为未知；证据齐备但存在未处置阻断仍不得为可验收；阻断豁免后才为可验收；派生过程不改变需求修订。
- 需要处理在打开项目后即可派生，活动事件可导出到项目导出目录。
- 非按钮节点与表格按钮单元格的分裂动作（`act` + `value`）被重新拼成工作台动作并正确路由；列表选择、标签切换等既有事件不受影响。
- 每页节点键唯一、动作全部接入宿主、输入键可路由（含 `activityQuery` 与 `layout`）。
