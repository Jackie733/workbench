# 阶段 2：原生需求工作台

日期：2026-11-11。插件 3.1.0。阶段 2 的需求池、详情编辑、搜索／筛选／排序、看板与项目存储已接通；正式批准、执行归属、代码证据、审计与验收仍属于后续阶段。

实现按职责命名：`lib/ui.luau` 负责原生视图组合，`host.luau` 负责状态与交互；阶段编号只用于计划、协议和验收文档，不用于运行模块名。

## 界面

- 项目页首显示项目名、编辑权限、绑定 omp 的真实状态／模型；不把“可编辑”当作 omp 正在工作。
- **需求**：列表、标题／目标／标签检索、阶段和优先级筛选、最近更新／编号／优先级排序。
- **看板**：八个常规阶段，阻塞／取消单独分组；与列表共用记录及筛选，不提供绕过批准／验收的拖拽。
- **详情／编辑**：标题、目标、范围、逐行验收条件、类型、优先级、标签。仅标题和目标必填。创建固定进入需求池，编辑不改变业务阶段。
- **运行**：会话状态、工具、原生 todo 的真实任务与计数、回复候选元数据，以及显式资料预填。不按心跳、工具成功或 idle 推断需求完成。
- **诊断**：完整路径、会话／pane 标识、原始事件和原始回执，默认页不再堆这些信息。

窄面板在列表和详情间切页；宽面板选择需求后显示列表与详情。布局依据实际 BlockCx.cols，而不是另开常驻窗格。

## 保存与恢复

打开先只读加载；新项目明确选择隐私方式再初始化，已有项目通过页首“启用编辑”取得写入权。其他窗口的新鲜租约不能抢占，过期后也必须明确接管。

草稿保留文本、光标／选择、类型、优先级、稳定创建 ID 和编辑起始 revision；撤销历史只放内存，不随每个按键复制进 KV。重载恢复同一编辑页；写入 token 放在具体 block 的保存状态，不由项目内多个窗口共享。重载后仍先只读，明确启用编辑才能继续保存。

保存期间字段不可编辑，避免异步成功后清掉更新的输入。重试复用创建 ID；版本冲突保留草稿，展示磁盘上全部可覆盖字段，只有明确选择保留整份草稿并基于该版本继续，才更新保存前置版本。不会静默最后写入覆盖。

创建使用完整 staging 目录再发布，重载中断只可能留下编号空洞和待排查 staging，不会发布空需求目录。详细协议及 77 项生产传输检查见 [存储记录](PHASE_2_STORAGE.md)。

## 预填边界

“用作资料草稿”只带入需求正文。已有不同资料草稿或待核对请求时不替换。运行页另需点击“预填到此会话（不发送）”；扩展还会核对来源、会话、忙碌状态和 omp 输入框草稿。已有 omp 草稿时明确拒绝，不覆盖、不按 Enter、不调用模型，也不自动重试未知结果。

重复 `/wb` 更新来源证明，不重置同项目的业务草稿或写入权。异常插件加载留下的无表面空壳，仅在来源已证明且用户再次 `/wb` 时替换；不认领或关闭其他来源的工作台。

## 本轮真实桌面验证

环境：Windows Tern 0.9.16，WSL Ubuntu，omp 18.18.7，隔离中文路径 Git 项目。测试 omp 指定 `openai-codex/gpt-6-luna`，未向模型发送测试提示，未修改日常会话内容。

已实际操作：

- 打开只读不创建项目；显式初始化和过期锁接管。
- 中文 IME `preedit`／`commit`；emoji 选择替换与撤销；多行目标、验收条件及原生下拉选择。
- 创建中文高优先级缺陷与低优先级第二项需求，真实写入、编号、修订和再次保存。
- 编辑中重载，完整表单与草稿恢复，原 block token 可再次启用编辑。
- 搜索只显示匹配需求；看板沿用筛选；优先级排序及低优先级筛选。
- 外部更新 revision 后保存被拒；草稿不丢，完整磁盘字段可滚动审阅，再明确继续保存。
- 约 492 px 窄面板列表／详情切页；宽面板主从布局。
- 不同需求不能覆盖已有资料草稿；omp 预先输入“已有草稿，不要覆盖”后，预填收到 `draft_conflict`，输入保持原文。
- 重复 `/wb` 后仍是一份原 omp＋一份工作台，没有新增执行会话。

活动计划的非空真实模型运行本轮未另行发起，不把空闲夹具当作运行中进度验证；原实时桥协议与历史验证见 [阶段 0＋1 记录](PHASE_0_1.md)。

## 开发注意

Tern 会因链接插件目录的文件变化热重载；把截图写进该目录的 `target/shots` 也会触发。因此不要在保存尚未完成时生成源码目录内截图。本轮确实复现过该中断，并据此增加真实回调取消恢复回归，而非隐藏错误或忽略损坏目录。

截图等 `target/` 产物不进入版本库。项目初始化不会迁移旧版任务；旧 KV 和方案仍保留，迁移按阶段 6 显式进行。
