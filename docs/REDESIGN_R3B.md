## 1. E4 决定（本轮采用的边界）

| 项 | 决定 |
| --- | --- |
| 持久化 | **不新增持久 schema**。队列与运行状态只在内存；重载丢弃运行状态，已完成证据仍按现有证据文件保留。 |
| 规模 | 最多 5 条；总时长 10 分钟；单条沿用既有 180 秒进程超时。 |
| 执行 | 严格串行；一次只有一个批量；不并行、不自动重试、不自动续跑。 |
| 停止条件 | 首个非 `passed`（含 `failed`／`unknown`）、验证后代码变化、总时长超限、用户请求停止。 |
| 取消 | 只停止调度：当前命令可能继续运行并如实记录结果；剩余命令标记未运行，不宣称进程已终止。 |
| 归属 | 每条命令沿用现有验证路径：先读代码快照、执行、记录退出码／输出／条件、再读快照；证据逐条保存。 |
| 冻结 | 开始批量时冻结命令与条件副本；之后编辑草稿不影响运行中的批量。 |

未做：跨机器/跨窗口共享批量、断点续跑、批量级总超时以外的资源配额、把剩余命令自动重排。

## 5. 已知限制

- 批量队列不持久化：重载后需要重新编排；这是为避免引入未批准的批量 schema 与恢复协议。
- 取消不保证终止正在运行的进程；界面与文档都不这样宣称。
- 真实桌面/真实命令下的总时长、逐步快照与停止行为仍需按 V11 执行。
